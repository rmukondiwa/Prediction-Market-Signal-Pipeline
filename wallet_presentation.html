Wallet Batch Fetcher

Account snapshot — balance and all open positions in a single command
Parallel Fetch
Balance and positions are requested simultaneously using asyncio.gather. Neither call waits on the other, minimising total round-trip time.
Auto-Paginated
The positions endpoint returns 100 records per page. The script follows cursors automatically until all positions are collected, regardless of account size.
RSA-PSS Auth
Reuses the same request-signing logic as the live WebSocket pipeline. Each request is freshly signed with a millisecond timestamp to satisfy Kalshi replay protection.

How It Works

Four stages from command to output
1
Sign the request
Each API call is signed with the RSA private key using PSS padding. The signature covers the current timestamp, HTTP method, and endpoint path — computed fresh per call to pass Kalshi's replay protection checks.
2
Fire balance and positions in parallel
asyncio.gather(fetch_balance(), fetch_all_positions()) — both calls hit the API simultaneously, cutting total wait time roughly in half versus sequential requests.
3
Page through all positions
The positions endpoint is cursor-paginated at 100 records per page. The fetcher re-signs and re-requests until the API returns an empty cursor, accumulating every open position.
4
Render table or raw JSON
Default output is a formatted terminal table. The --json flag emits raw JSON, suitable for piping into other scripts or the inference engine.

Positions are sorted by absolute size descending. Positive position = YES contracts held. Negative = NO contracts. P&L values are converted from Kalshi's internal cent denomination to dollars.
